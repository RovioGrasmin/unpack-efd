================================================================================
  unpack_efd.py — РАСПАКОВЩИК ФАЙЛОВ ПОСТАВКИ 1С (.efd)
  Извлекает .cf / .cfu и дополнительные файлы из дистрибутивов 1С на Linux/CLI
================================================================================

НАЗНАЧЕНИЕ
--------------------------------------------------------------------------------
Дистрибутивы конфигураций и обновлений 1С (например "Управление торговлей")
поставляются в виде файла 1cv8.efd внутри установочного пакета. Штатный
установщик 1С (setup) — графический (GTK), на сервере без рабочего стола не
запускается. Данный скрипт извлекает содержимое .efd НАПРЯМУЮ, в командной
строке, без графики и без установки чего-либо.

Из .efd извлекаются:
  - 1cv8.cf   — полная конфигурация (в дистрибутиве ПОСТАВКИ);
  - 1cv8.cfu  — файл обновления     (в дистрибутиве ОБНОВЛЕНИЯ);
  - сопутствующие файлы (ReadMe.txt, UpdInfo.txt, доп. обработки и т.п.).


ТРЕБОВАНИЯ
--------------------------------------------------------------------------------
- Python 3 (любой современный, проверено на 3.12 / Ubuntu 24.04).
- НИКАКИХ внешних библиотек и pip-пакетов. Используется только стандартная
  библиотека Python (zlib, struct, os, tempfile, datetime).
- Свободное место на диске: примерно равное размеру распакованного содержимого
  (для крупных поставок — несколько ГБ; временный буфер пишется в системный
  каталог TMPDIR).


ИСПОЛЬЗОВАНИЕ
--------------------------------------------------------------------------------
    python3 unpack_efd.py <файл.efd> <папка-назначения>

Параметры:
    <файл.efd>           путь к распаковываемому файлу поставки/обновления
    <папка-назначения>   каталог, куда извлечь содержимое (создаётся при
                         необходимости; внутри воссоздаётся структура каталогов
                         из дистрибутива)


ПРИМЕРЫ
--------------------------------------------------------------------------------
1) Извлечь ПОЛНУЮ конфигурацию из поставки:
    python3 unpack_efd.py /путь/TradeBase/1cv8.efd /tmp/ut_supply
   Результат: .../1c/trade/<версия>/1cv8.cf

2) Извлечь файл ОБНОВЛЕНИЯ:
    python3 unpack_efd.py /путь/update/1cv8.efd /tmp/ut_update
   Результат: .../1c/trade/<версия>/1cv8.cfu

Найти извлечённый .cf / .cfu:
    find /tmp/ut_supply -iname '*.cf'
    find /tmp/ut_update -iname '*.cfu'


ЧТО ДАЛЬШЕ (загрузка / обновление конфигурации, CLI)
--------------------------------------------------------------------------------
Полная загрузка конфигурации в пустую базу (.cf):
    1cv8 CONFIG /S "СЕРВЕР\БАЗА" /N "Пользователь" /P "пароль" \
       /LoadCfg /tmp/ut_supply/.../1cv8.cf /UpdateDBCfg -Server \
       /DisableStartupMessages /DisableStartupDialogs /Out /tmp/load.log

Применение обновления (.cfu):
    1cv8 CONFIG /S "СЕРВЕР\БАЗА" /N "Пользователь" /P "пароль" \
       /UpdateCfg /tmp/ut_update/.../1cv8.cfu /UpdateDBCfg -Server \
       /DisableStartupMessages /DisableStartupDialogs /Out /tmp/update.log

Ключи /DisableStartupMessages и /DisableStartupDialogs обеспечивают тихий
(без диалоговых окон) пакетный режим.


КАК ЭТО РАБОТАЕТ (кратко, формат EFD)
--------------------------------------------------------------------------------
Файл .efd целиком сжат алгоритмом RAW DEFLATE (zlib без заголовка, wbits=-15).
После распаковки получается контейнер со структурой (все числа little-endian):

  header        : uint32  (= 1, версия формата)
  supply_count  : uint32  (число блоков описания поставки)
  supply_info[] : по supply_count: 4 байта + 4 строки (язык, имя комплекта,
                  поставщик, путь к описанию)
  files_count   : uint32  (число вложенных файлов)
  file_info[]   : по files_count: 4 байта + имя + filetime(uint64) + 4 байта
                  + размер(uint32)
  <данные>      : тела файлов подряд, ровно по "размер" байт каждый

  Строка        : uint32 длина-в-символах, далее длина*2 байт в кодировке UTF-16.

Скрипт распаковывает поток deflate потоково (буфер на диске), читает каталог
файлов и сохраняет тела файлов, воссоздавая исходную структуру каталогов.


КОДЫ ЗАВЕРШЕНИЯ И ОШИБКИ
--------------------------------------------------------------------------------
- "Файл не найден"                — неверный путь к .efd.
- "Неизвестный формат EFD"        — файл не является .efd (header != 1).
- "Файл оборван при чтении"       — .efd повреждён/недокачан.


БЕЗОПАСНОСТЬ (для ревью)
--------------------------------------------------------------------------------
- Скрипт НЕ обращается к сети, НЕ запускает внешние процессы, НЕ требует прав
  root. Только чтение входного .efd и запись файлов в указанный каталог.
- Весь код — в одном файле, без внешних зависимостей; алгоритм прозрачен и
  поддаётся построчному аудиту.
- Корректность подтверждена: побайтовое (MD5) совпадение результата с
  эталонной реализацией.
