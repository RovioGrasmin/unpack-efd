# `unpack_efd.py` — распаковка поставок и обновлений 1С (`.efd`) без графического установщика

**Что это.** Один файл на 113 строк, чистый Python 3 stdlib, который достаёт из дистрибутива 1С `1cv8.efd` файлы `.cf` / `.cfu` и сопутствующие документы — на сервере без рабочего стола, в одну команду.

**Зачем.** Автоматизация обновлений 1С на Linux. Пока `.cfu` не извлечён, обновлять нечего.

**Главное.** Ни одной сторонней библиотеки: только стандартная библиотека CPython. Ни `pip`, ни `venv`, ни форков, ни вендорных патчей. Именно это делает его пригодным для закрытых контуров, где установка сторонних пакетов запрещена, а любой скрипт проходит ревью по строкам.

---

## 0. Почему «ванильный Python» — не мелочь, а суть

Инструментов для `.efd` в мире хватает (см. раздел 10). Проблема не в том, что «нечем распаковать», а в том, что **нечем распаковать на сервере, куда нельзя поставить pip-пакет**.

Что именно даёт отсутствие сторонних зависимостей в контуре с жёсткими требованиями:

| Требование при аудите | Что даёт stdlib-only |
|---|---|
| Нет цепочки поставок (supply chain) | нет PyPI, нет транзитивных зависимостей, нечего проверять на компрометацию пакета |
| Нет установки ПО | файл кладётся и запускается; `pip` в системе может быть запрещён политикой |
| Построчный аудит | 113 строк в одном файле читаются целиком за один проход |
| Фиксация артефакта | один файл = одна SHA-256, её можно закрепить в регламенте |
| Минимальная поверхность атаки | нет сети (`socket`/`urllib` не импортируются), нет `subprocess`, нет `sudo`, нет вызова внешних бинарей |
| Совместимость с базовым образом | работает на том Python, который уже есть в ОС; интерпретатор не надо ставить |

Оговорка для честности: «без зависимостей» здесь означает **без сторонних пакетов**. Интерпретатор и его stdlib (включая `zlib`, который в CPython — встроенный C-модуль) нужны, и это надо прямо писать в заявке, а не говорить «зависимостей нет вообще».

## 1. Проблема

Дистрибутивы типовых конфигураций и обновлений 1С поставляются как файл `1cv8.efd` внутри установочного пакета (`setup` / `setup.x86_64`). Штатный установщик — графический: он тянет GTK и на сервере без X не стартует. В итоге типовой сценарий «скачал обновление на сервер → применил через `1cv8 CONFIG … /UpdateCfg`» упирается в то, что `.cfu` ещё лежит внутри `.efd`, а распаковать его штатно нечем.

Штатные варианты и почему они не подходят:

| Вариант | Почему нет |
|---|---|
| `setup.x86_64` (графический установщик) | требует GTK/X, падает на headless |
| Клиент 1С + Конфигуратор в GUI | та же история, нужен рабочий стол |
| `onec_dtools` (pip) | умеет `.efd`, но тянет пакет и venv — в закрытом контуре это отдельное согласование |
| `efd_unpacker` (PyQt5) | рабочий, но GUI и PyQt5 в зависимостях |
| `v8unpack` | это про внутренний формат `.cf`/`.epf`, а не про контейнер поставки |

Нужен был инструмент, который запускается на голом сервере, не требует pip и поддаётся построчному аудиту.

## 2. Формат `.efd` (по результатам разбора)

Формат нигде внятно не описан, поэтому структура восстановлена анализом файла. Проверено на поставке и на обновлении «Управления торговлей 11.5».

### 2.1. Внешний слой — один поток RAW DEFLATE

Весь файл целиком сжат `zlib` **без заголовка**, то есть `wbits = -15`. Это не ZIP и не tar: ни оглавления, ни пароля, ни отдельных потоков на файл — один непрерывный deflate-поток на весь `.efd`.

### 2.2. Внутренний слой — контейнер, всё little-endian

После распаковки получается плоский контейнер:

```
header          : uint32   (= 1, версия формата)
supply_count    : uint32   (число блоков описания поставки)
supply_info[]   : supply_count раз:
                    reserved     : 4 байта
                    lang         : строка
                    supply_name  : строка
                    provider_name: строка
                    description  : строка (путь к описанию)
files_count     : uint32   (число вложенных файлов)
file_info[]     : files_count раз:
                    reserved     : 4 байта
                    filename     : строка (путь в стиле Windows, разделитель `\`)
                    filetime     : uint64 (FILETIME — 100-нс интервалы с 1601-01-01)
                    reserved     : 4 байта
                    file_size    : uint32 (размер в байтах)
<данные файлов> : тела подряд, ровно по file_size байт
```

**Строка** в этом формате: `uint32` длина **в символах**, затем `длина × 2` байт в **UTF-16** (little-endian).

Обратите внимание: каталог файлов — плоский список с путями, а не дерево. Тела лежат строго подряд, поэтому «каталог» читается целиком, а потом файлы вычитываются последовательно.

---

## 3. Почему чистая стандартная библиотека

Изначальное требование — минимум зависимостей, потому что скрипт запускается на серверах заказчика и проходит ревью по безопасности. Отсюда:

- только `zlib`, `struct`, `os`, `sys`, `tempfile`;
- один файл, без пакетов, без установки, без venv;
- нет обращений к сети, нет вызова внешних процессов, нет `sudo`;
- алгоритм прозрачен и проверяется построчно.

`onec_dtools` при этом использовался — но **как эталон сверки**, а не как зависимость (см. раздел «Проверка корректности»).

## 4. Как работает

### 4.1. Потоковая распаковка в файл, а не в память

Поставка — это гигабайты, поэтому распаковка идёт блоками по 10 МБ в `tempfile`, а не в `BytesIO`:

```python
decompressor = zlib.decompressobj(-15)
while True:
    chunk = src.read(CHUNK)
    if not chunk:
        break
    buf.write(decompressor.decompress(chunk))
buf.write(decompressor.flush())
```

`-15` — это и есть «raw deflate без zlib-заголовка».

### 4.2. Чтение строк

```python
def read_string(f):
    char_len = unpack('I', f.read(4))[0]
    return f.read(char_len * 2).decode('utf-16')
```

Длина в символах, а не в байтах — типовая ошибка при разборе таких форматов.

### 4.3. Пропуск описания поставки

Блок `supply_info` для извлечения файлов не нужен, но его обязательно надо прочитать, чтобы встать на нужное место:

```python
for _ in range(supply_count):
    buf.read(4)              # reserved
    for _ in range(4):       # lang, supply_name, provider_name, description_path
        read_string(buf)
```

### 4.4. Каталог и тела

Сначала читается весь каталог (имена и размеры), затем тела — строго по `file_size`, с воссозданием структуры каталогов:

```python
for filename, file_size in files:
    rel_parts = filename.split('\\')          # пути внутри EFD всегда Windows-стиля
    path = os.path.join(os.path.abspath(output_dir), *rel_parts)
    os.makedirs(os.path.dirname(path), exist_ok=True)
    with open(path, 'wb') as out:
        remaining = file_size
        while remaining > 0:
            data = buf.read(min(CHUNK, remaining))
            if not data:
                raise EOFError('Файл оборван при чтении: %s' % filename)
            out.write(data)
            remaining -= len(data)
```

## 5. Использование

```bash
# извлечь полную конфигурацию из поставки
python3 unpack_efd.py /path/TradeBase/1cv8.efd /tmp/ut_supply
find /tmp/ut_supply -iname '*.cf'

# извлечь файл обновления
python3 unpack_efd.py /path/update/1cv8.efd /tmp/ut_update
find /tmp/ut_update -iname '*.cfu'
```

Дальше — применение платформой, в тихом пакетном режиме:

```bash
# первичная загрузка конфигурации в пустую базу
1cv8 CONFIG /S "СЕРВЕР\БАЗА" /N "Пользователь" /P "пароль" \
  /LoadCfg /tmp/ut_supply/.../1cv8.cf /UpdateDBCfg -Server \
  /DisableStartupMessages /DisableStartupDialogs /Out /tmp/load.log

# применение обновления
1cv8 CONFIG /S "СЕРВЕР\БАЗА" /N "Пользователь" /P "пароль" \
  /UpdateCfg /tmp/ut_update/.../1cv8.cfu /UpdateDBCfg -Server \
  /DisableStartupMessages /DisableStartupDialogs /Out /tmp/update.log
```

`/DisableStartupMessages` и `/DisableStartupDialogs` — то, без чего пакетный режим виснет на первом же диалоге.

## 6. Проверка корректности

Главный вопрос к любой обратной разработке формата: «а не выдумал ли автор структуру?». Проверка была такой:

1. Распаковать `.efd` этим скриптом.
2. Распаковать тот же `.efd` через `onec_dtools` (эталонная реализация).
3. Сверить **MD5** извлечённого `.cf`/`.cfu` — совпадает побайтово.
4. Дополнительно: извлечённый `.cfu` штатно применяется платформой 1С (`/UpdateCfg`).

То есть формат разобран не «на глаз», а подтверждён независимой реализацией и самой платформой.

### 6.1. Перекрёстная проверка по чужому парсеру

Дополнительно структура сверена с независимой открытой реализацией — [`IngvarConsulting/efd_unpacker`](https://github.com/IngvarConsulting/efd_unpacker) (исходники MIT, GUI на PyQt5). Их модуль разбора оглавления совпадает с нашим по всем ключевым точкам:

| Элемент формата | Этот скрипт | `efd_unpacker` |
|---|---|---|
| Версия контейнера | `header != 1` → ошибка | `SUPPORTED_HEADER = 1` |
| FILETIME | 100-нс интервалы от 1601-01-01 | `FILETIME_EPOCH = datetime(1601, 1, 1)` |
| Раскладка | оглавление, затем тела подряд | «оглавление в начале потока, данные следом» |
| Сжатие | `zlib`, raw deflate (`wbits=-15`) | `zlib` |
| Границы | поставки до нескольких ГБ | крупнейшая исследованная — 2,96 ГБ, оглавление в первых 3 КБ |

Две независимые реализации, пришедшие к одной структуре, — это лучший аргумент, чем «у автора получилось». Если в будущем понадобится расширять скрипт, их код — удобная точка сверки.

## 7. Грабли

1. **Место во временном каталоге.** Буфер пишется в `TMPDIR` и занимает примерно столько же, сколько распакованное содержимое (для крупных обновлений — гигабайты). На маленьком диске лечится `TMPDIR=/big/disk python3 unpack_efd.py …`.
2. **`file_size` — `uint32`.** Формат не умеет файлы больше 4 ГБ. Для 1С это неактуально, но ограничение стоит держать в голове.
3. **Время файлов не восстанавливается.** `FILETIME` читается и отбрасывается: mtime у извлечённых файлов будет «сейчас». Лечится легко — `datetime(1601,1,1) + timedelta(microseconds=filetime/10)` + `os.utime`.
4. **Zip-slip.** Имя из контейнера подставляется в путь как есть. Для дистрибутивов 1С это безопасно, но если гонять через скрипт файлы из недоверенных источников — надо отбрасывать `..` и абсолютные пути.
5. **`header != 1`.** Значит это не `.efd`: например, в скрипт случайно подсунули `.cf` или `.cfu`.
6. **Обрыв потока** — «Файл оборван при чтении»: файл недокачан или повреждён.
7. **Скрипт ничего не применяет.** Он только извлекает. Загрузка и обновление — задача платформы (`/LoadCfg`, `/UpdateCfg`).

## 8. Ограничения

- Работает только с контейнером поставки (`.efd`). Внутренний формат `.cf`/`.epf` — это другая задача (`v8unpack`).
- Не проверяет подписи и контрольные суммы дистрибутива.
- Не поддерживает `.efd` с иной версией контейнера (`header != 1`) — на момент написания таких не встречалось.

## 9. Что можно улучшить

- `--verify` — сверка размеров и, опционально, MD5 с манифестом.
- Санитизация путей (защита от `..`).
- Восстановление mtime из `FILETIME`.
- Прогресс-индикатор для больших поставок.
- Чтение из stdin (`cat 1cv8.efd | python3 unpack_efd.py - /out`).

## 10. Альтернативы

Инструменты существуют — вопрос не в «нечем распаковать», а в том, что можно поставить на конкретный сервер.

| Инструмент | Что умеет | Почему не подошёл здесь |
|---|---|---|
| [`efd_unpacker`](https://github.com/IngvarConsulting/efd_unpacker) (IngvarConsulting) | распаковка `.efd`, GUI + headless CLI, Windows/Linux/macOS | GUI на PyQt5, сборки под GPL v3, ставится как приложение |
| [`onec_dtools`](https://pypi.org/project/onec_dtools/) | 1CD, `.cf`, `.epf`, **`.efd`**; библиотека `extract`/`build` | пакет с зависимостями, нужен pip/venv — в закрытом контуре отдельное согласование |
| [«Распаковщик EFD файлов»](https://infostart.ru/1c/tools/710201/) на Infostart | распаковка `.efd` | сторонний бинарь с сайта, не аудируется |
| Плагин `*.EFD` для Total Commander | просмотр архивов `.efd` | Windows + Total Commander |
| `v8unpack` | внутренний формат `.cf`/`.epf`, не контейнер поставки | не про `.efd` |
| `setup.x86_64` от 1С, `1cv8 DESIGNER` | штатно | GUI, на headless-сервере не работают |

Ниша этого скрипта узкая и конкретная: **headless-сервер, где запрещены сторонние пакеты, а скрипт проходит ревью по строкам.**
